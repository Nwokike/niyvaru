# Plan: Finish Niyvaru — Stabilization, Depth, Performance, Verification

## Context

The current build has the main product shape in place: city-agnostic runtime assembly, full-page brand homepage, 3D map, Discover Dossier, Happening tab, non-blocking walk HUD, memory/agent, and a failure-only gateway retry. The remaining work is to make it complete and dependable rather than merely functional.

Three read-only explorations found concrete gaps:

- **Map fragility**: the basemap error path calls `setStyle(bare)`, wiping custom POI/route layers; initial hour and topbar clock can disagree; debug handles leak; mobile fit/zoom and time controls are weak.
- **Data/agent depth**: stories attach by fuzzy title but photos only within 150 m with a 4-photo cap, so dossiers often have no imagery. The agent over-calls `search_places` / `nearby` / `place_details` because there is no tool economy rule or dedupe.
- **Completion hygiene**: docs are obsolete, `pmtiles` is unused, `adhan` is misclassified as a dev dependency, no automated check gate exists, and there has not yet been the required dependency-source study or pre-ship verifier pass.

Binding constraints remain: **100% free/open dependencies**, **city-agnostic runtime data**, **no hardcoding of cities/content/endpoints**, **mobile-first performance**, **no upfront context pruning** — only the existing failure-triggered retry may compact context.

## 1. Stabilize the Map Core

### `src/map/style.ts`, `src/map/mapView.ts`, `src/map/pois.ts`
- Replace the destructive `map.setStyle(bare)` fallback with a recoverable path:
  - Emit a fallback event or resolve `ready` after fallback style load.
  - Re-add `places`, `routes`, terrain, hillshade, and building layers after any style replacement.
  - Export an `ensureCustomLayers(map)` helper from `pois.ts` and call it on both initial and fallback `style.load`.
- Sync time-of-day:
  - Pass the App's current browser-derived hour into `initMap` or call `api.setHour(tod)` immediately after map init.
  - Remove the hardcoded `18.5` as the effective starting point; keep it only as a neutral fallback when no hour is supplied.
- Clear `window.__niyvaruMap` and `window.__niyvaruRegrade` in `destroy()` so area changes never leave stale debug state.
- Pass and honor `AbortSignal` in map init.
- Make `focusPlace`, route `fitBounds`, and walk camera padding responsive using viewport size and the existing city bounds; avoid fixed desktop padding on mobile.

### `src/App.tsx`, `src/styles.css`
- Ensure the time slider is available on mobile or provide an equally usable compact control.
- Keep topbar, ambient pill, panel, and walk HUD from colliding at ≤720 px.

## 3. Stop Agent Tool Loops Without Reducing Intelligence

### `src/agent/prompt.ts`, `src/agent/facts.ts`
- Add explicit tool-economy rules to the system prompt:
  - AREA DATA already contains the near place list and ids; reuse it.
  - One tool call per distinct intent.
  - Never re-run `search_places`, `nearby`, or `place_details` with minor query rewrites.
  - If a tool returns nothing, say so instead of retrying.
- Make the facts header explicitly state that listed ids are ready to use.

### `src/agent/tools.ts`, `src/agent/runtime.ts`
- Add a closure-local dedupe map inside `createAgentTools()` keyed by tool name + normalized arguments.
- Repeated read-only calls return the cached result plus a short note: “already retrieved — use the earlier result”.
- Add a repeated-signature stop condition as a backstop alongside `isStepCount`, but do not lower model capability or prune context upfront.
- Keep `gateway.ts` failure-only compaction exactly as the user requested: retry only on HTTP 500/400/exhausted responses.

## 6. Performance and Build Hygiene

### `src/App.tsx`, `src/ui/ChatPanel.tsx`, `vite.config.ts`, `src/main.tsx`, `public/sw.js`
- Lazy-load `ChatPanel` so the large `agent` chunk is not preloaded on first paint.
- Use the existing `deviceLowPower()` result to gate terrain, hillshade, extrusions, and navigation detail on low-powered mobile devices.
- Cap or spatially prioritize rendered POIs while keeping the full pack in data/agent memory.
- Load only the font subsets needed per locale where practical.
- Update the service worker to avoid stale preload problems and handle lazy chunks gracefully.

### `package.json`, `vite.config.ts`
- Move `adhan` from devDependencies to dependencies.
- Remove unused `pmtiles` dependency and its manual chunk entry, since the current OpenFreeMap source is TileJSON rather than PMTiles.
- Add a lightweight `npm run check` script: typecheck, build, and assert `dist/assets/maplibre-gl-worker.mjs` exists.
