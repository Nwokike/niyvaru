# Final UX/UI Polish Pass — Every Step of Niyvaru

## Context

The implementation is complete and pushed (`99f24b8`). A dedicated final research pass compared the live app against the user-provided reference material for `niyvaru.eu` and *City in Relief*, plus current map/form/accessibility patterns. The app now works end-to-end, but several first-session details still feel unfinished: unclear city confirmation, hidden search affordance, no submit feedback, weak chat/dossier empty states, hidden zoom controls, frozen reduced-motion walk progress, unlocalized notices, and mobile/RTL/touch-target issues.

The goal is not another feature phase. It is to make the existing experience feel deliberate, trustworthy, and polished throughout: homepage → form → assembly → map → discover → happening/story/memory → walk, on desktop and mobile, in English and Arabic.

The original `niyvaru.eu` hero copy stays because the user explicitly asked for it. It will be reconciled with the city-agnostic engine by adding an explicit, visible city-selection state and a small “any city on Earth / free / open / no account” trust line.

---

## 1. Homepage + Form: make intent unmistakable

### `src/ui/Intake.tsx`, `src/config/i18n/en.ts`, `ar.ts`, `src/styles.css`
- Keep the two-column brand hero and original Makkah/Madinah hotel-concierge copy.
- Add a compact trust line under the hero lede: city-agnostic, free/open, no account.
- When search results arrive, **auto-select the first result visibly** (`stay`, `onPickArea`) and show a confirmation line: “Exploring {city}. Choose another result to change it.” Keep the typed-query fallback, but the selection must never be invisible.
- Add a visible Search button (plus Enter), clear stale results when the query changes, add `aria-live` result count / “Nothing found” status, and show the 2-character minimum hint.
- Add a submitting state: disable CTA, show spinner, and label “Saving your answers…”. Only switch views after memory writes succeed.
- Validate optional dates only when both are present: check-in must not be after check-out. Use a localized error.
- Mark non-required fields inline as optional; remove unused `datesRequired` or wire it to the new validation.
- Add `role="alert"` to warnings and `aria-pressed` to chips / toggle cards; stepper buttons get localized `aria-label`s via existing `d.intake.fewer/more`.
- Add safe-area padding and a sticky CTA area on narrow screens.

## 2. Assembly: calm, localized, honest progress

### `src/ui/Assembling.tsx`, `src/sources/assemble.ts`, `src/App.tsx`, i18n dictionaries
- Replace raw pipeline details (`overpass unavailable`, `3 shard`, `routing 7 walks`) with localized, human-readable lines based on stage keys and counts.
- Move `aria-live` from the whole loader to the stage list only; hide the elapsed timer from assistive tech.
- Keep “Step in” gated on places being ready; if a nonessential stage failed, show one plain sentence before entry (“Photographs are unavailable here; the map still works.”).
- Add a short “Saved — assembling {city}” acknowledgement before the reveal.

---

## 3. Explore + Discover Dossier: shallow, readable, synced

### `src/ui/DiscoverDossier.tsx`, `src/ui/PlaceCard.tsx`, `src/ui/BriefPanel.tsx`, `src/App.tsx`, `src/map/mapView.ts`, `src/styles.css`, i18n
- Always show a photo frame: real photo when available, otherwise a neutral icon + “No photo available for this place.” No blank gaps.
- Fix alt text: describe the place or use `alt=""`; keep attribution in visible captions/tooltips. Apply across dossier, place card, brief, and assembling hero.
- Clamp long story extracts to ~4 lines with an explicit “Read more”, keeping walk/ask actions visible.
- Make next/prev targets ≥44px, label buttons with the actual next/previous place name, and show a small hint: “Use ← → or swipe · tap pins on the map.”
- Scope dossier keyboard handling: ignore inputs, textarea, select, buttons, and `contentEditable`; keep Escape/arrow behavior only when the dossier is truly active.
- Track swipe X **and** Y; only navigate when horizontal movement dominates. Add `touch-action: pan-y`.
- Shorten repeat camera flights to ~700–900ms; keep the long cinematic flight for first entry. Cancel in-flight animations when selecting another place.
- Add a visually hidden, keyboard-reachable list of the top ~60 places with buttons that focus each place. This gives screen-reader/keyboard users parity with canvas POIs.
- Add honest coverage line: “Coverage varies by city — some places have no photo or story yet.”

## 4. Happening / Story / Memory: make each tab honest and useful

### `src/ui/PulsePanel.tsx`, `src/ui/BriefPanel.tsx`, `src/ui/MemoryPanel.tsx`, i18n
- Label device-local notes “You · this device · not shared”, using `d.pulse.you`; add a visible badge.
- Localize relative times with `Intl.RelativeTimeFormat`, prayer names via dictionary, sponsored fallback, and the trailing loading text.
- Story tab: localize kind counts via `d.explore.layers`; render facts as plain text, not fake clickable chips; use `d.discover.source` instead of hardcoded “Wikipedia”.
- Keep the Story tab name, but show a real area summary built from assembled facts + honest empty state when no narrative exists.
- Memory panel: add explicit Edit/Save affordance, saved-state feedback, import success/error, localized status strings, and restore focus to the edit button after modal close.

---

## 5. Map controls + time-of-day

### `src/App.tsx`, `src/map/mapView.ts`, `src/styles.css`, i18n
- Move zoom/compass controls out from under the side panel: `top-left` with a top offset below the header; mobile offset below the wrapped topbar.
- Give the time control a real label (“Time of day”) and `aria-valuetext` (“18:30 · Golden”). State that it follows **your local clock**; do not pretend it is destination time.
- Fix reduced-motion camera behavior: use `jumpTo` or `flyTo` with `essential: false`; never force animation with `essential: true`.
- Defer map initialization until the view leaves the homepage; selecting a form chip must not load tiles behind an opaque page.
- Add `role="alert"` and a real dismiss button to notices; localize all user-facing error strings (`map failed`, `walk imagery unavailable`, `no walking route`, `change area`).

---

## 6. Walk: integrated, interruptible, honest

### `src/walk/player.ts`, `src/styles.css`, `src/App.tsx`, i18n
- Change the overlay from `role="dialog"` to `role="region"` (non-modal); focus Stop on start and restore previous focus on end.
- Ignore Space/Escape when the user is typing in input/textarea/select/contentEditable.
- Add a “Follow map” toggle; stop camera updates while the user is dragging or after they turn follow off.
- Reduced-motion mode becomes a complete static photo album: show total distance and a Done/Return button; remove the frozen progress bar/ETA.
- On mobile, hide the normal panel during a walk and present one compact bottom sheet with photo, HUD, Pause/Stop, and safe-area padding.
- Localize route name and all walk labels; show the route start point (area centre / “from map centre”) before playback.

---

## 7. RTL, focus, and touch polish

### `index.html`, `src/styles.css`, `src/config/i18n/index.ts`, i18n dictionaries
- Bootstrap `lang` and `dir` early from saved/browser locale to avoid LTR flash.
- Use logical properties for the language select and notice positioning; disable wide letter-spacing / uppercase for Arabic eyebrow text.
- Use `bdi`/`Intl.NumberFormat` for mixed numbers and units in Arabic.
- Expand focus-visible ring and add forced-colors outline; remove remaining `outline: none` without replacement.
- Raise small text/captions and ensure 44px hit areas for steppers, dossier arrows, close buttons, and time controls.
- Add a collapsible Layers row so filters do not push the chat input below the fold on mobile.
