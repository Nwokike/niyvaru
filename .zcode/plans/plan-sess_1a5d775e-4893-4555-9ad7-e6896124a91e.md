# Niyvaru — city-agnostic world map experience (rebuild)

## Context

The existing prototype contradicts the product at every level and hardcodes a place: neon dev theme vs the real warm paper/bronze brand (extracted from niyvaru.eu's stylesheet), a fake seeded community post, a single-image slideshow "walk" whose frames don't match the drawn route (one route is a mislabeled 7.3 km driving fallback), a hardcoded default area + gateway key + UI strings, no real memory, no area selector.

The binding correction from the user: **the product is not a Makkah/Madinah tour. It is a modular, world-scale map experience — any city on Earth (New York, Lagos, anywhere) — where selecting a city downloads that city's information in real time.** No city may be compiled into the app: no bundled city imagery, no Saudi-specific code paths, no build-time store of one city's pictures. Makkah is merely the first *dataset* the engine loads, and even it arrives through the same runtime path as every other city.

Standing rules: **nothing paid, ever**; **zero hardcoding** (colors, strings, people, areas, endpoints, policies, imagery — all config/data or fetched live); **modular interfaces** (inventory source, feed registry, memory policy, geocoder, router are swappable adapters); **mobile-first performance is non-negotiable**; **complete scope, no phased MVPs**; iterations verified in the browser with the user watching.

## Core architecture

Static Vite + React + TS app (100% client-side, free stack). Two data paths, one schema:

1. **Runtime area assembly (the system of record — the user's explicit wish).** The traveller searches **any city on Earth** (Photon geocoder, user-triggered, Nominatim fallback — both keyless, CORS; endpoints are config) or picks from a featured manifest (a data file, editable without code). Selecting an area defines a bbox; the app then **downloads the area live** through a provider layer and caches the result in IndexedDB as a local area pack (versioned, refreshed on revisit):
   - **Places**: Overpass API (keyless, CORS) — POIs for the bbox with accessibility tags (wheelchair/entrance/kerb), opening hours, phones, websites, cuisine/shops, gates.
   - **Imagery**: Wikimedia Commons geosearch (real photos of any landmark worldwide, keyless, CORS) + Panoramax federation (keyless) + Mapillary (free token in config) — place photos, street frames, hero visuals for the welcome screen. **No city imagery ships in the bundle — everything is fetched for the selected city.**
   - **Narrative**: Wikipedia geosearch (multilingual) per landmark.
   - **Routes**: FOSSGIS OSRM pedestrian instance (the keyless walking router openstreetmap.org itself uses; CORS) with OSRM demo fallback — real walking routes for any city; foot profiles only (fixes the driving-fallback bug).
   - **Pulse**: GDELT geo query (free/open, no key) + Bluesky Jetstream WebSocket + Mastodon hashtags from the area's feed config; prayer times computed locally by coordinates (method from area config — a generic worldwide feature, not a Saudi one); weather via provider adapter (MET Norway where a identifying UA is possible — e.g. the optional Worker mode — with the adapter chain in config; sources without CORS route through the existing optional Worker).
   - All runtime fetches cached in IndexedDB; stale entries refresh in the background; nothing blocks first paint.

2. **Prebuilt pack acceleration (optional, same schema, same loader).** A build-time job uses the **same source adapters** (shared code) to pre-generate packs for featured areas — a CDN cache, not a different system. Featured areas live in a data manifest; adding Lagos is adding a manifest entry or just searching for it.

## Workstreams

### 1. Brand design system (city-neutral — from the extracted niyvaru.eu stylesheet)
- `src/brand/tokens.ts` + `tokens.css`: paper `#fbf7f1`, cream/sand/linen, ink, bronze/deep/brass, Playfair Display + Cormorant Garamond display, DM Sans body, **Noto Sans Arabic** companion, ease `cubic-bezier(.22,1,.36,1)`, signature primitives (`.arch` masks, film grain, bronze hairline, eyebrow, rise/fade). Full `prefers-reduced-motion` path.
- Fonts self-hosted via @fontsource. No city photographs in the bundle — welcome visuals come from the selected area's live imagery.
- Replace `src/styles.css` entirely; all components rebuilt in brand language.

### 2. Config spine (kills every hardcode)
- `src/config/`: `endpoints.ts` (gateway URL/key via env, geocoder, routers, Overpass, Commons, Panoramax, Mapillary token, GDELT — every endpoint swappable), `areas.ts` (registry loaded from data, not code), `feeds.ts` (per-area pulse sources/hashtags as data), `memory-policy.ts` (block caps, retention, delete→archive — policy as data), `i18n/en.ts` + `ar.ts` (complete RTL), provider adapters registry.
- `src/inventory/types.ts`: inventory-source interface — the hotel-selection step (`select_candidates`) runs over whatever source is connected (area pack now, private wholesale feed later) — nothing assumes a human or a city.
- Remove: `DEFAULT_AREA`, gateway-key default in code, hardcoded routes, fake posts, mood enum.

### 3. Source adapter library (`src/sources/` — shared by runtime assembly and the optional pack builder)
One adapter per source with a common interface + IndexedDB cache layer: `geocode.ts` (Photon/Nominatim), `overpass.ts`, `commons.ts`, `wikipedia.ts`, `panoramax.ts`, `mapillary.ts`, `walkingRoutes.ts` (FOSSGIS foot router), `gdelt.ts`, `social.ts` (Bluesky/Mastodon), `weather.ts`, `prayer.ts` (local computation, any coordinates). Each adapter: typed results, graceful failure, attribution metadata carried through.

### 4. Map experience (`src/map/`)
- MapLibre + OpenFreeMap style **re-graded to brand tokens programmatically** (no hex in layer code); world-scale — opens on the searched city, not a hardcoded center.
- `buildings3d.ts` (fill-extrusion on OSM heights, rising z15→16, cream→bronze by height), `terrain.ts` (Mapterhorn DEM + sky, capability-gated), `timeOfDay.ts` (dawn/day/dusk/night palettes as data, smoothstep blend, sun-following light — the Lisbon-reference relighting), `pois.ts` (clustered layers + brand DOM markers, kind filters incl. accessibility), `camera.ts`, city-search + area-picker UI (anywhere on Earth).

### 5. Walk experience (`src/walk/`)
- Route-aligned real imagery (runtime-matched frames by proximity+heading along the fetched route), two-layer GPU crossfade, preload window, brand HUD, narration cues from any verified-walk data that exists for the area (per-area data files — present where curated, absent nowhere-required), honest coverage labeling, 3D camera flythrough fallback along the route, reduced-motion photo-strip mode.

### 6. Agent (`src/agent/`) — client-only, typed tools, city-agnostic
- AI SDK v6 `ToolLoopAgent` + `useChat` + `DirectChatTransport` over the Kiri Gateway (OpenAI-compatible provider; roster/fallbacks in config). The hand-rolled `<niyvaru>` parser is deleted.
- Tools (Zod-validated, all client-side): `search_places`, `nearby`, `place_details`, `photos_for_place`, `focus_poi`, `highlight_kinds`, `clear_view`, `show_route`, `start_walk`, `set_view`, `set_time_of_day`, `get_now` (pulse/weather/prayer for the *current area*), `get_place_story`, `draft_area_brief`, `select_candidates` (over the inventory interface), `memory` (six commands below).
- Prompt assembled from brand voice + policy + the current area's compact facts — the agent speaks only verified data and works identically in Makkah, New York, or Lagos.

### 7. Memory engine (`src/memory/`) — agent-managed, policy-driven
- IndexedDB (`idb`) store: memory files (`traveller.md`, `trip.md`, `journal.md`, `places.md`, plus per-area notes) with YAML frontmatter; core blocks always in context; append-only archive; chat window; vector-ready schema.
- `search.ts` (Orama keyword+recency), `memoryTool.ts` (Anthropic memory-tool command spec: view/create/str_replace/insert/rename/delete, delete→archive per policy), `blocks.ts` (budgeted context assembly each turn).
- Intake: the brand's chip/toggle-card selector (dates, party+ages, mobility, budget, interests, language) writes the memory files directly — the AI's context starts from real data. Demo scenarios as data files only.
- Export/import; `navigator.storage.persist()`; PWA install prompt (Safari 7-day exemption); Memory/Ops viewer-editor (privacy-first).

### 8. Pulse surface (`src/pulse/`) + area brief (`src/brief/`)
- Registry-driven "Now" rail on the map for the current area: GDELT, Bluesky, Mastodon, Wikimedia, weather/prayer, local posts (device-local, keyed to memory). Per-item source attribution.
- Area brief renderer: the selected city's story (Wikipedia narrative + Commons imagery + facts), shareable, JSON-LD; site-level `llms.txt` + `agents.md` (GEO).

### 9. App shell, PWA, i18n, performance
- `App.tsx` rebuilt: city select → area assembles with visible progress → explore (map + chat), pulse, brief, memory/Ops. PWA manifest + service-worker precache (app shell only; area data caches via IndexedDB); en/ar complete RTL; localized map labels.
- Performance budget (mobile-first): capability-gated 3D/terrain, zoom discipline, clustering, lazy area assembly with progress UI, parsing in workers, AVIF/WebP for any processed imagery, preloaded walk frames, Lighthouse mobile gate.
- README/docs rewritten to match reality (honest limits, source attributions).

### Dependencies (all free/open-source)
`ai` v6 + `@ai-sdk/react` + OpenAI-compatible provider, `zod`, `idb`, `orama`, `@fontsource/*` (4 fonts). Kept: maplibre-gl, pmtiles, adhan.
